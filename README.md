# robust-fair-ev-siting

Code for the article *Efficient plans dodge, fair plans hedge: forecast uncertainty and the robust fairness premium
in electric vehicle charging siting* (under review).

The pipeline forecasts zone-level charging energy, turns forecast errors into zone-wise conformal radii, solves
budgeted capacitated coverage MILPs for four plans (nominal or robust, efficient or fair), decomposes the robust
fairness premium (RFP), tests the dodging mechanism with permutation layouts of the radii, and finds the
largest feasible fairness floor with and without distribution-feeder voltage limits.

**No data or results are included.** The public datasets are downloaded from their original repositories, and every
number in the paper is regenerated by the scripts below.

## Repository layout

```
src/                 experiment code (run from this folder or through scripts/run_all.sh)
  common.py          dataset selection (EVDATA), chronological splits, shared loaders
  exp1_forecast.py   day-ahead forecasts: SNaive, DLinear, GRU, Graph-GRU, iTransformer
  exp2_gradient.py   zone-wise conformal radii and drivers of error heterogeneity
  exp3_siting.py     four siting plans, RFP decomposition, uniform and rank-flipped radii, feeder limits
  exp4_alignment.py  permutation test of the radius layout (dodged and ex ante dodgeable shares)
  exp5_fair_ceiling.py  fairness ceiling tau* by bisection, with LinDistFlow IEEE-33 feeders
  bound_check.py     tightness of the dodging bound (Proposition 2)
  diagnostics.py     radius coverage on test days and ex ante dodgeable shares
  preprocess_charged.py, diag_sites.py   cleaning and zoning of the CHARGED cities
  calibrate_grid.py  choice of feeder count and base load (optional)
scripts/
  download_data.sh   fetches UrbanEV and CHARGED into data/
  run_all.sh         runs every experiment in stages
analysis/
  summarize_results.py  prints the tables and statistics of the paper from outputs/
  make_figures.py       writes Figures 1-7 to outputs/figures/
```

## Data

* UrbanEV (Shenzhen traffic zones): <https://github.com/IntelligentSystemsLab/UrbanEV>
* CHARGED (multi-city charging records): <https://github.com/IntelligentSystemsLab/CHARGED>, `*_remove_zero` folders

Please cite the original dataset publications and respect their licences. `scripts/download_data.sh` places the
files under `data/urbanev/` and `data/charged/<CITY>/`; `src/preprocess_charged.py` writes the cleaned zone
systems to `data/proc/<CITY>/`, including the coverage radius of each city in `meta.json`.

## Installation

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt   # install the PyTorch build that matches your CUDA version first
```

Tested on Linux with the package versions in `requirements.txt` (Python 3.10 or later). The MILPs use SciPy's HiGHS interface (`scipy.optimize.milp`); no commercial
solver is needed.

## Reproducing the paper

```bash
bash scripts/download_data.sh
bash scripts/run_all.sh            # all stages
# or stage by stage:
bash scripts/run_all.sh forecast   # GPU recommended
bash scripts/run_all.sh heterogeneity
bash scripts/run_all.sh siting
bash scripts/run_all.sh permutation
bash scripts/run_all.sh ceiling
bash scripts/run_all.sh peak
bash scripts/run_all.sh models
bash scripts/run_all.sh checks
bash scripts/run_all.sh summary    # prints outputs/summary.txt and writes outputs/figures/
```

Independent jobs within a stage run in parallel; set `JOBS` to the number of CPU cores you want to use and `PY` to
the Python interpreter. The siting, permutation and ceiling stages are CPU-bound and dominate the run time; a
many-core machine is recommended.

### Main switches

| Variable / flag | Meaning |
|---|---|
| `EVDATA=urbanev` or `EVDATA=charged_<CITY>` | dataset (`AMS`, `JHB`, `LOA`, `MEL`, `SPO`, `SZH`) |
| `RADIUS=hourly` (default) or `RADIUS=peak` | conformal radius on hourly errors or on daily-peak errors |
| `EV_RFP_ROOT` | project root holding `data/` and `outputs/` (default: repository root) |
| `--radius_km` | coverage radius; default 3 km for UrbanEV and the data-derived value in `meta.json` for CHARGED |
| `--gamma(s)`, `--tau(s)`, `--beta(s)` | Bertsimas-Sim budget, fairness floor, budget as a share of full-service cost |
| `--fmult` | fixed site cost as a multiple of median forecast demand |
| `--grids M1 M2 M3`, `--feeders`, `--vmin`, `--base_scale` | feeder mapping, number of IEEE-33 copies, voltage limit, base-load scale |

### Outputs used by each figure

| Figure | Files in `outputs/` |
|---|---|
| 1 | schematic, no data |
| 2 | `zone_radii_A.csv`, `gradient_tests.csv`, `coverage_by_group.csv`, `charged_*/gradient_tests.csv` |
| 3 | `rfp_{A,B}_iTransformer.csv`, `charged_{SZH,LOA}/rfp_C_iTransformer.csv` |
| 4 | `alignment_{A,B}_iTransformer_g2_p100.csv`, `charged_{SZH,LOA}/alignment_C_iTransformer_g2.csv` |
| 5 | `alignment_{A,B}_*_g*.csv` (all sensitivity settings) |
| 6 | `fair_ceiling_iTransformer.csv`, `charged_{SZH,LOA}/fair_ceiling_iTransformer.csv` |
| 7 | `rfp_{A,B}_iTransformer.csv` (ex post columns) |

Forecasts are trained with three seeds; GPU non-determinism can change the last digits of the radii and hence of
the downstream quantities, but not the qualitative results.
